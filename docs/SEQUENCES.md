# Показательные сиквенсы

Хронология «как это ощущается» — для проверки архитектуры на живых кейсах
и как онбординг для новых сессий.

## A. «Транскрибация встречи» — файл, долгая работа, вопрос «куда»

**T0 · телефон.** Человек создаёт карточку `ME-42` «Транскрибация встречи 12.10»:
описание «транскрибация + диаризация; задачи нарезать на „Рабочие задачи"»,
файл — в `~/.kan/inbox/2026-10-12-planerka.m4a` (имя в описании), карточка →
«к исполнению».

**T1 · вахтёр (≤60 с, без LLM).** Diff: карточка вошла в «к исполнению» →
замок: move→«в работе» + коммент `wake runId=…` → спавн
`pi -p --session-id kan-ME-42 "<контракт + payload: вошла в к исполнению>"`.

**T2 · пробуждение №1 — план.** Агент читает карточку, кладёт «План»
чек-листом: `[скачать файл из inbox][проверить инструменты ASR/диаризации]
[транскрибировать][диаризация][вопрос: куда сохранять][нарезка задач на
„Рабочие задачи"][итог-коммент + на согласование]`. Забирает файл, готовит
`~/.kan/tasks/ME-42/`. Транскрибация часа — десятки минут: **не держит ход**
— фоновый job, коммент «запущено, ETA ~40 мин», ход окончен, процесс умер.

**T3 · self-wake.** Job доделал → сам пишет коммент
`<!--kan:job run=…-->готово: transcript.md, 4 спикера, 58 мин`. Вахтёр видит
коммент с job-тегом → будит **ту же сессию** событием «job завершился».
Вечноживущего процесса нет: очередь событий — планировщик.

**T4 · пробуждение №2 — вопрос.** Агент вычитывает диаризацию, упирается в
«куда сохранять» → коммент «Куда сохранить? Варианты: NFS
`Meetings/2026-10-12-planerka/` или укажи путь» → move→**«на согласовании»**.
Ждёт хоть неделю — он не процесс.

**T5 · телефон.** Коммент: «в `Meetings/октябрь/`, задачи с дедлайнами».
Вахтёр: человеческий коммент на активной карточке → пробуждение №3.

**T6 · пробуждение №3 — исполнение.** Сохраняет транскрипт+сводку на NFS.
Читает борду «Рабочие задачи» (агенту можно; вахтёр её не поллитит),
дедуплицирует, создаёт карточки экшенов. Итог-коммент в `ME-42`: путь +
ссылки на N карточек + «Бригада: …», чек-лист ✓, → «на согласовании».

**T7 · закрытие — только человек.** `ME-42` → «завершены». Сессия `kan-ME-42`
— архив задачи: `pi --session-id kan-ME-42` вернёт всю кухню («а где ты взял,
что спикер 2 — Иванов?»).

## B. «Поднять ВМ с GitLab» — тяжёлая работа через субагента

**T0.** Карточка с описанием и требованиями → «к исполнение».
**T1.** Вахтёр: замок, пробуждение.
**T2.** План чек-листом; исполнение — делегирование профильному субагенту
(поднятие ВМ, установка); субагентный отчёт — **файлом** в
`~/.kan/tasks/ME-43/`. Один ход может съесть 5–10 субагентных шагов без
единого сообщения человеку.
**T3.** Итог-коммент (IP, доступность, проверено чек-листом) →
«на согласовании». Человек тащит в «завершены».

Упади сессия на середине — не страшно: карточка в «в работе» с комментом-
замком, следующее событие продолжит с того же контекста; чек-лист покажет,
на каком пункте всё встало.

## C. «Письмо с согласованием» — комменты как аудит-трейл

```
карточка «письмо Иванову» [черновик][апрув][отправка]
 1. агент: черновик → коммент с текстом → «на согласовании»
 2. человек с телефона: «ок, но убери п.2 и проверь цену»
 3. пробуждение: правка → коммент «версия 2» → «на согласовании»
 4. человек: «отправляй»
 5. пробуждение: отправил → чек-лист [x][x][x] → коммент «Message-ID …»
    → «на согласовании» → человек: «завершены»
```

Каждый шаг переживает рестарты; цепочка «агент предложил → человек решил →
агент сделал» зафиксирована в карточке с авторами и временем. В чате такой
аудит-след стоит отдельной ручной работы.

## D. Собака, которая ест себя

Первая задача на борде — «сделать расширение pi-kan»: карточка будит сессию
`kan-ME-1`, которая пишет код этого репозитория, гоняет тесты, коммитит.
Борда кормит сама себя с первого дня (dogfooding как метод разработки).
