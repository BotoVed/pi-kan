# Конфигурация pi-kan

Двухуровневая схема. **Хост** знает креды и пути; **борда** — политику, и она
живёт на самой борде. Правила проектирования — [ARCHITECTURE.md §10](ARCHITECTURE.md);
здесь — справочник ключей и рецепты.

---

## Уровень 1. Хост — `~/.kan/config.json`

Только доступ: куда ходить и чем. Ни одной политики.

| Ключ | Тип | Описание |
|---|---|---|
| `url` | string | Базовый URL инстанса Kan.bn **без** `/api/v1` (например `http://192.168.10.132:3000`) |
| `tokenFile` | path | Файл с API-ключом Kan, `chmod 600`. Токен никогда не хранится в конфигах и на борде |
| `kanRoot` | path | Рабочий корень: `tasks/<cardId>/`, `inbox/`, `state.json`, `keeper.log`. По умолчанию `~/.kan` |

Переменные окружения (dev/несколько инстансов): `KAN_CONFIG` (путь к конфигy),
`KAN_URL`, `KAN_TOKEN_FILE`, `KAN_ROOT` — переопределяют соответствующие поля.

Несколько инстансов Kan = несколько `kanRoot` + отдельные юниты хранителя.

## Уровень 2. Борда — карточка `.pi-kan`

Подписка борды = **создание карточки с заголовком `.pi-kan`**. Её **описание**
содержит JSON-политику (в описании, не в комментарии — единственный
идемпотентный канал). Удалили карточку — борда отписана. `enabled: false` —
пауза с сохранением настроек.

Создаёт и заполняет карточку `/kan init` — руками JSON писать не нужно
(это источник №1 багов «опечатался в publicId»).

### Скелет (его и создаёт `/kan init`)

```json
{
  "lists": {
    "backlog": "sr6hheujr8js", "ready": "cke228uhnuop",
    "inProgress": "dx2iqkhr8jje", "review": "j5ox7zczwiwj",
    "done": "bws1chkx8ige"
  },
  "pollIntervalSec": 60,
  "maxConcurrent": 2,
  "wake": { "model": null, "thinkingLevel": null },
  "events": {
    "comments": true, "descriptionEdits": true,
    "checklistEdits": true, "dueDate": true
  },
  "enabled": true,
  "host": null
}
```

### Ключи

| Ключ | Тип | По умолч. | Значение |
|---|---|---|---|
| `lists` | объект | **обязателен** | publicId'ы пяти списков борды: `backlog`, `ready`, `inProgress`, `review`, `done`. Все пять — строки ≥1 симв; без этого конфиг невалиден |
| `pollIntervalSec` | число | `60` | Интервал опроса API борды, **≥ 10** (реже — бережём троттл ключа ~60 req/мин) |
| `maxConcurrent` | число | `2` | Сколько сессий-задач может идти одновременно (глобально по хранителю) |
| `wake.model` | string \| null | `null` | Модель для пробуждаемых сессий (`provider/id`). `null`/отсутствует → флаг не передаётся, действует дефолт pi-конфига хоста |
| `wake.thinkingLevel` | string \| null | `null` | Уровень размышления сессий (`off…max`). `null` → дефолт хоста |
| `events.comments` | bool | `true` | Будить на человеческие комментарии |
| `events.descriptionEdits` | bool | `true` | Будить на правки описания карточки |
| `events.checklistEdits` | bool | `true` | Будить на правки чек-листа |
| `events.dueDate` | bool | `true` | Будить на установку/просрочку dueDate |
| `enabled` | bool | `true` | Рубильник борды: `false` — хранить состояние, но не будить |
| `host` | string \| null | `null` | **Кем** мониторить борду, когда несколько хостов делят один токен: `hostname` хранителя (`keeper.log` печатает свой). `null` — кто первый встал |

Неизвестные ключи верхнего уровня — **warning, не ошибка** (обратная
совместимость при расширении схемы). Вложенность — только показанная выше.

### Валидация и безопасность

- **Секреты на борде запрещены конструктивно**: любой ключ в дереве,
  похожий на `url` или `token*`, — ошибка валидации whole-конфига. Поэтому
  борда безопасна для глаз команды, а её правки не могут увести креды.
- Невалидный/недописанный JSON (классика — правка с телефона) — хранитель
  живёт на **last-known-good** из локального кэша, а вину пишет комментом в
  ту же `.pi-kan`. Хранитель не падает, борда не отписывается.
- WYSIWYG-редактор Kan пересохраняет ```json-блок как HTML `<pre><code>` —
  парсер читает оба вида, редактирование в веб-морде безопасно.
- `.pi-kan` — **не задача**: её правки не будят сессии (конфиг-событие), а
  мандат-гард блокирует агенту любое движение/редактирование/удаление этой
  карточки. Агент не может ни отписать борду, ни ослабить себе поводья.

### Идентификация

Заголовок `.pi-kan` — конвенция **первого** поиска. Далее хранитель держит
publicId конфиг-карточки в кэше (`state.json`) — переименование карточки
после подписки не ломает ничего, но лучше не надо.

## Рецепты

**Пауза борды** (отпуск/обслуживание): в описании `.pi-kan` → `"enabled": false`.
Настройки и подписка сохраняются, пробуждений нет.

**Сменить модель задачам этой борды**: `"wake": { "model": "anthropic/claude-…", "thinkingLevel": "high" }`.
Следующее пробуждение подхватит (горячая перезагрузка не нужна).

**Только человек-очередь, без комментов**: `"events": { "comments": false, "checklistEdits": false }` —
будить только перемещениями в «к исполнению» (и описаниями, если не отключить).

**Отписать борду**: удалить карточку `.pi-kan`. Вернуть: `/kan init <борда>`.

**Два хоста, одна борда** (например, рабочий и домашний pi): у нужного хоста
в `.pi-kan` `"host": "<hostname хранителя>"`; у второго поле оставить `null`
или вписать его — иначе второй хост борду не мониторит.

**Перенос борды/инстанса**: `~/.kan/state.json` — кэш, можно удалить (первый
тик соберётся заново); `tasks/` — рабочая память задач, переносить целиком.

## Диагностика

| Симптом | Куда смотреть |
|---|---|
| Борда не будится | `~kan/keeper.log`: подпись найдена? `enabled`? `host` совпадает? коммент-ошибка в `.pi-kan`? |
| Конфиг не принят | Коммент-ошибка хранителя в карточке `.pi-kan` (там же, где преступление) |
| `/kan init` не находит списки | Имена: бэклог / к исполнению / в работе / на согласовании / завершены (создаст сам, если не хватает) |
| 429 от Kan | Общее: хранитель + сессии делят один ключ; уменьшите `pollIntervalSec` агрессивность (увеличьте интервал), уменьшите `maxConcurrent` |
