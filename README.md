# pi-kan

Расширение [pi](https://github.com/badlogic/pi-mono) (coding agent harness), превращающее доску [Kan.bn](https://github.com/kanbn/kan) в рабочий интерфейс агента: **хранитель-демон** следит за бордой и будит **сессии-задачи**, а весь диалог «человек ↔ агент» живёт комментариями на карточках.

> «Тот же чат, но на доске.»

## Идея в трёх абзацах

**Карточка = задача, сессия = память задачи.** Каждая карточка в очереди «к исполнению» будит процесс агента с детерминированным ID сессии (`pi -p --session-id kan-<cardId>`). Между событиями процесс умирает, но контекст задачи остаётся в файле сессии — и следующее пробуждение продолжает с полного рабочего состояния, а не с микротекста карточки.

**Хранитель — скрипт, не LLM.** Демон без модели опрашивает API борды, детектирует diff (карточка вошла в «к исполнению», новый человеческий коммент, dueDate), сам ставит замок (перемещение + коммент с runId) и спавнит сессию с payload-диффом события. Вся интеллектуальная работа — в проснувшемся агенте.

**Борда — единственный реестр.** Никакой локальной базы задач: «в работе» = активные сессии, «на согласовании» = ждут человека, «завершены» ставит только человек. Состояние переживает смерть любой сессии, рестарт машины и апгрейды.

## Статус

Фаза 1: скелет (watcher-демон + контракт + конвенции борды). Без вебхуков, без внешних зависимостей — единственный внешний мир это Kan.bn по HTTP (REST для вахтёра, MCP для агента).

## Не является

- ❌ Telegram/пуш-ботом — уведомления живут на борде; пуши — внешний мостик, не часть ядра.
- ❌ Чат-ботом с памятью в модели — память в файлах сессий и артефактах задач.
- ❌ Очередью для «длинных чатов» — чат неудобен для длинных задач; борда — нет.
